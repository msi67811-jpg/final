# 여러 샘플 누적 비교와 가속화 실험 (8회차 멘토링 후속, 2026-11-23)

`COMPARE_LOCAL.md`는 1명, 사진 1쌍 결과였다. 이 문서는 같은 지표를 공개 얼굴 10쌍과 사용자 1쌍(u01)에 적용한 결과다.
- **샘플별 지표와 평균:** 모델 원본과 후처리(입술만 합성)를 나란히 둔다. 이것이 "전·후 누적"이다.
- **가속화 가능성:** 모델마다 기준 설정과 빠른 설정을 비교한다. 비교 항목은 시간과, 기준 출력에서 얼마나 달라졌는지다.

```bash
# 샘플 준비 → AR 렌더(ar_tune_render.mjs) → FPMT 기준·가속(CPU) → RunPod(Stable-Makeup, MagicMakeup) → 평가
research/data/makeup_gen/.venv/Scripts/python.exe research/makeup_gen/prep_samples.py
research/data/makeup_gen/.venv/Scripts/python.exe research/makeup_gen/fpmt_accel.py research/data/fpmt/quick_start research/data/makeup_gen
#   RunPod: research/makeup_gen/runpod/run_sm_multi.py, run_mm_multi.py
research/data/makeup_gen/.venv/Scripts/python.exe research/makeup_gen/eval_multi.py research/data/makeup_gen
```
결과 파일은 모두 `research/data/makeup_gen/multi/`에 있고 git에서 제외된다.
- `eval/multi_metrics.json`: 샘플별 전체 행
- `eval/multi_table.md`: 전체 표
- 그림 2장: `eval/fig_multi_lip_dE.png`, `eval/fig_multi_speedup.png`

## 1. 샘플과 조건

- **공개 10쌍 (p01–p10)**
  - 맨얼굴: FPMT 저장소 예시 `non_makeup` 중 정면이고 입을 다문 10장. 빠진 3장은 0491(입 벌림·고개 돌림), 0058(고개 돌림), 0409(입 벌림)이다.
  - 레퍼런스: `makeup` 중 입술색이 다른 5장이다. 코랄 #EA8682, 레드 #C03347, 로즈 #CA3A70, 누드 #975B5E, 버건디 #651438. 맨얼굴 i번에는 레퍼런스 i%5번을 짝지었다.
  - 정답: 레퍼런스 입술 CIELAB 중앙값이다. 그래서 이 숫자는 **"다른 사람 사진의 입술색을 옮기는 정확도"**다. 실제로 발랐을 때의 색을 예측하는 정확도는 아니다.
- **사용자 1쌍 (u01):** `COMPARE_LOCAL.md`의 A(맨얼굴)와 E(실제로 바른 사진)다. 정답이 실제 발색인 유일한 쌍이지만, E가 레퍼런스이면서 정답이라 순환이 있다. 평균은 공개 10쌍과 11쌍 전체로 따로 낸다.
- **AR:** 레퍼런스 입술 hex를 그대로 넣었다. 설정은 기존 기본값 glossy 0.65와 matte 0.50이다. 720×960 프레임에서 같은 세션의 AR 끈 프레임과 비교했다.
- **모델:** 모두 seed 0이고, 각 모델의 출력 크기에서 쟀다(FPMT·Stable-Makeup 512, MagicMakeup 1024).
  - FPMT는 노트북 CPU(i5-1135G7)에서 돌렸다.
  - Stable-Makeup·MagicMakeup은 RunPod NVIDIA A40(46GB)에서 돌렸다. 가동 약 1시간 35분, 약 $1. Pod는 종료했고 업로드한 데이터는 지웠다(데스크톱 Claude 실행 보고 `multi/runpod_handoff/RUNPOD_RESULT.md`).
- **지표:** `COMPARE_LOCAL.md`와 같은 함수를 쓴다.
  - 차이 하나: "입술 밖" 영역을 모든 샘플에서 얼굴 랜드마크 볼록 껍질로 정했다. 그래서 u01의 입술 밖 값은 `COMPARE_LOCAL.md`와 0.1~0.15 다를 수 있다.

- **FPMT:** CPU에서 가장 가볍지만 장당 3.5초 아래로는 내려가지 않았다. 입력을 256으로 줄여도 시간이 같았다. 해상도와 무관한 부분이 시간을 대부분 쓰는 것으로 보이지만, 원인은 따로 재지 않았다.
- **Stable-Makeup:**
  - fp16이 품질 변화 거의 없이(0.13) 2.6배 빠르고 VRAM도 절반이다.

  - fp16과 스텝 축소를 함께 쓰는 경우는 재지 않았다.
- **MagicMakeup:** 가장 빠른 8스텝도 장당 67초다. 실시간이나 앱 대기 시간 안에 쓸 수 없다.
  - 스텝을 줄였을 때 입술 ΔE가 오히려 조금 낮아졌다(3.65 → 3.14). 3쌍뿐이라 경향으로 보지 않는다.

## 5. 해석

1. **1쌍에서 본 순위가 10쌍에서도 유지된다.**
   - 레퍼런스 입술색을 옮기는 정확도는 FPMT(1.8) > MagicMakeup(3.0) > Stable-Makeup(5.4) 순이다.
   - FPMT는 10쌍 모두 3.2 이하로 편차가 가장 작다.
   - u01에서 FPMT 0.69, MagicMakeup 3.61은 `COMPARE_LOCAL.md`(11-20 A6000 실행) 값과 같아, 다른 GPU에서도 재현됐다.
   - Stable-Makeup u01은 2.50이다. 표의 2.70과 다르고, GPU와 환경이 다르다(11-20 Colab T4).
2. **후처리(전·후)**
   - 입술 밖 변화는 세 모델 모두 0이 되고, 입술 색 오차는 거의 그대로다(±0.3 안팎).
   - **색 차이만** 합성하면 맨입술 결이 돌아온다. 주름 상관은 Stable-Makeup 0.35 → 0.90, MagicMakeup 0.65 → 0.92로 오른다. Stable-Makeup은 입술 결을 많이 지우는데, 후처리로 회복된다.
3. **AR은 진한 색에서 레퍼런스 색에 닿지 않는다.**
   - AR에도 레퍼런스 hex를 넣었는데 평균 9~11이다.
   - 맨입술과 목표색 차이가 큰 쌍에서 오차가 크다(버건디·레드, 맨얼굴 ΔE 23~39). 차이가 작은 쌍(p01, p09, u01; 맨얼굴 4~6)에서는 2.4~4.9다.
   - 이유는 셰이더가 진하기 0.5~0.65로 맨입술 색을 섞고, 카메라 밝기(명암·주름)를 유지하기 때문이다. `docs/AR_SPEC.md` 6-5-3("스티커가 아니라 직접 바른 것처럼") 설계 의도와 맞다.
   - 그래서 이 지표는 AR에 불리하다. 이 숫자로 AR 색 정확도를 결론 내리지 않는다.
   - u01처럼 정답이 실제 발색인 쌍에서는 AR 2.4로 Stable-Makeup(2.5)과 비슷하다. 진하기 1.0 조건은 재지 않았다.
4. **앱 결론은 `COMPARE_LOCAL.md` 3장과 같다.** 실시간 렌더는 AR이 맡는다. 생성 모델 중 가속 후에도 오프라인 도구로 쓸 만한 것은 FPMT(CPU 3.5초)와 Stable-Makeup(fp16, A40 3.4초)이다.

## 6. 한계

- 공개 샘플은 MT 데이터셋 계열이라 동아시아 여성 위주다. 피부톤 다양성이 부족하다.
- 공개 샘플은 FPMT 학습 분포에 가까울 수 있어, **FPMT에 유리하다.**
- 정답이 레퍼런스 입술색이라 "옮기는 정확도"다. 실제 발색 예측은 u01 1쌍(순환 포함)뿐이다.
- seed는 0 하나다. seed 편차는 `COMPARE_LOCAL.md`의 1쌍 3 seed 결과만 있다.
- 가속 실험은 3쌍이다. GPU 시간은 A40 한 종류이고, Pod 안에서 다른 작업이 없을 때 쟀다(첫 장은 워밍업 후 다시 쟀다).
- 사용자 사진(u01)과 그 결과(`multi/out/*/u01.png`, `runpod_handoff/runpod_inputs.zip`)는 공유하지 않는다.

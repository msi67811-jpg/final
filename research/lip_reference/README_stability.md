# 립 추적 안정성 측정 (P1-2)

같은 영상으로 기기·빌드가 달라도 떨림·끊김을 같은 방법으로 비교한다. 영상·결과는 `research/data/` 아래에만 둔다(Git 제외, 외부 공유 금지).

## 실행
```bash
# 영상은 영문 경로에 둔다(OpenCV가 한글 경로를 못 읽는 경우가 있음)
python research/lip_reference/eval_stability.py research/data/ar_eval_public/stability/<clip>.mp4
```
출력: 콘솔 요약 표, `<clip>_stability_frames.csv`(프레임별), `<clip>_stability_summary.csv`(요약).
앱과 같은 평활화는 `faceTrackerHtml.ts`의 `TUNING.smoothMinCutoff / smoothBeta / smoothDCutoff`를 읽어 쓴다(값을 복사하지 않음).

## 지표
| 지표 | 뜻 |
|---|---|
| `jitter_rel` | 얼굴이 거의 안 움직이는 프레임에서 입술 점의 프레임 간 이동량 ÷ 입 너비. 중앙값·95% |
| `jitter_shape` | 위에서 입술 전체의 이동을 뺀 값. 앱 필터는 이동 성분을 일부러 거르지 않으므로(흔들면 같은 프레임에 따라감) 필터 효과는 여기서 보임 |
| `lip_iou_t` | 연속 프레임의 입술 마스크 IoU(깜빡임). 고개를 돌리면 자연히 낮아지므로 정지 프레임 값을 함께 본다 |
| `lost_rate` | 얼굴을 놓친 프레임 비율, 연속으로 놓친 최대 길이 |
| `lag_frames`, `trail_rel` | 고개를 움직일 때 평활화된 입술이 원본보다 얼마나 뒤처지는가(프레임), 최대 차이(입 너비 대비) |

"정지 프레임" = 얼굴 중심이 프레임당 입 너비의 1% 미만으로 움직인 프레임. 10장 미만이면 경고를 출력하고 떨림 수치는 대표성이 없다.
이 숫자는 **오프라인(PC) MediaPipe + 앱 필터 재현**이다. 폰에서 실제 돈 추적(GPU, 가변 FPS)과는 다르다. 칠해진 입술은 읽지 않는다(색 기준 분할이 반사·그림자를 피부와 구분 못 해 틀린 수치가 나옴).

## 실기기 촬영 절차 (iOS·Android 각각, 같은 조건)
1. 같은 방, 같은 조명, 폰을 손으로 들거나 거치대에 고정(조건을 기록: 기기·OS·조명·거치 여부).
2. 개발 모드 Expo Go → AR 탭 → 립 한 색 선택. 개발용 녹화 버튼(왼쪽 아래 빨간 원)으로 **10초** 녹화 → 끝내고 공유 시트에서 PC로 보낸다(없으면 폰 화면 녹화).
3. 이 순서로 움직인다: 정면 정지 3초 → 고개 좌우 → 고개 위아래 → 말하기 → (파운데이션이면) 앞머리 걷기/내리기.
4. 같은 시점에 디버그 HUD(화면 두 번 탭)의 FPS를 적어 둔다.
5. 영상마다 위 명령을 실행하고 요약 CSV를 모은다.

녹화 버튼 영상은 카메라 위에 메이크업이 그려진 AR 캔버스라서 입술이 칠해져 있다(추적에는 영향이 작지만 기기 간 비교에는 모두 같은 방식으로 찍을 것).

## 파운데이션 마스크 지연 측정 (11-02)
- `eval_foundation_lag.py CLIP.mp4`: 같은 영상에서 피부 마스크가 k프레임 묵었을 때(앱 설정: 120ms ≈ 4프레임, 20fps 미만이면 400ms ≈ 12프레임)의 얼굴 영역 오차와, 마스크를 얼굴 움직임대로 옮겼을 때 오차. 분할 모델(`selfie_multiclass_256x256.tflite`)은 앱이 쓰는 공개 URL에서 받아 `research/data/models/`에 둔다.
- `ar_eval_public/tools/render_found_mask.py`: 영상 프레임에 묵은/최신 마스크를 주입해 앱 셰이더로 파운데이션을 렌더(수정 전·후 페이지 비교). 기존 오프라인 렌더는 마스크가 없어서 이 경로를 못 본다.
- 영상의 중복 프레임 비율로 앱의 실제 갱신 속도와 100ms 이상 멈춤을 알 수 있다(화면 녹화가 30fps일 때).
